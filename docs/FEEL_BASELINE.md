# 歩き方と発見の演出の基準（2026-10-16 採用）

宝さがしを公開するとき（TOMORI-TREASURE-RELEASE-01）に、iPhone の実機で確かめて採用した値です。
今後、歩き方や演出を変えるときは、この値を出発点にします。
変えたときは、変える前と後を同じ距離・同じ画角の動画でくらべ、このファイルも書きかえてください。

数値はすべて `demo-world.html` の中にあります。かっこの中は、探すときの名前です。

## 歩き方（ヒロリ）

ねらいは「たったった」と一歩ずつの間が感じられる歩き方です。「タタタタ」と小走りに見える速さには戻しません。

2026-10-21 の指示（TOMORI-EXPLORATION-FLOW-02）で、歩く速さと一歩で進む距離を2倍にしました。足を動かす速さ（1秒に約4.4歩）は変えていません。この値は、iPhone の実機でまだ確かめていません。

| 項目 | 今の値（FLOW-02） | 2026-10-16 に採用した値 | 場所 |
|---|---|---|---|
| 歩く速さ（m/秒） | 6.6 | 3.3 | `SPEED` |
| 歩幅の周期（1周期＝左右1歩ずつで進む距離） | 3.0 | 1.5 | `STRIDE_RIG` |
| 足の前後の振れ | 0.17 | 0.1 | `RIG_REACH` |
| 足を前後に動かすうち、ずらして出す割合 | 0.4 | 0.45 | `RIG_SHIFT` |
| 足の上がる高さ | 0.075 | 0.05 | `RIG_LIFT` |
| 脚の回転の上限 | 0.75 | 0.6 | `RIG_SIN_MAX` |
| 体の上下 | 0.045 | 0.035 | `STEP_BOB` |
| 前かがみ | 0.11 | 0.07 | `STEP_LEAN` |
| 一歩の中の速さの強弱 | 0.32 | 0.22 | `STEP_PACE` |
| 仮ヒロリの1周期の距離 | 3.2 | 1.6 | `STRIDE_UNITS` |

- 1秒の歩数は、今も約4.4歩です（6.6 ÷ 3.0 ＝ 3.3 ÷ 1.5）。
- 速さ・歩幅・上下の揺れは、3つ一緒に調整します。速さだけを変えると、足がすべって見えます。
- 一歩が大きくなったぶん、足を前後に大きく出し、少し高く上げ、少し前かがみにしました。一歩の中の速さの強弱も大きくし、着地の前後をゆっくりにしています。足が地面に止まって見えるようにするためです。体の上下は少しだけ大きくし、跳ねすぎないようにしました。
- 止まる位置は前と同じで、タップした場所の 0.6m 手前です（`ARRIVE`）。1コマで進む量は残りの距離までなので、行き過ぎません。
- カメラの追いかけは、1コマごとに 0.08 寄せる方式から、時間で決める方式（0.11 秒）に変えました。進む向きへ 0.18 秒ぶん（最大 1.4m）先を見ます。速く歩いても、ヒロリが画面のはしへ行かないようにするためです。
- 「動きを減らす」設定の端末では、一歩の中の速さの強弱を止めます（`pace()` が 1 を返す）。カメラの先読みも、すぐに落ち着きます。
- 前後の比較動画：同じ距離（9m）・同じ画角で、前は 2.75 秒、今は 1.38 秒で歩きます。

## 世界の広さ（FLOW-02）

速さを2倍にしただけでは、近くの物にすぐ着いてしまいます。そこで、場所どうしの間をおよそ2倍に広げました。新しい速さでも、場所から場所へ歩く時間は前とほぼ同じです。

- 広げたのは場所どうしの間だけです。人・物・木・建物の大きさと、「調べる」が出る距離（2m）は変えていません。
- いっしょに置いてある物は、位置関係を変えずに動かしました。ねこと岩、オオネと巨木の根もと、橋と川、ミナのそばの丸い木などです。
- 古い石の門は、草原のふちのすぐ外（約0.6m）に置きました。道がひらく前でも、門をタップして近づけば「しらべる」を押せるようにするためです。
- 広がった草原の「場所と場所のあいだ」には、小さな木立と花の群れを足しました。景色を見ながら歩く区間にするためです。人・物・道・出発点の前には置きません。
- 霧・遠くの丘・影の範囲も、広さに合わせました。丘は2倍遠くなったので、高さを1.5倍にしています。影を作る範囲（48m四方）は、ヒロリといっしょに動きます。

## 近づいたときの案内と、木で隠れるとき（FLOW-02）

- 近づいただけでは、会話やミッションの大きなパネルを開きません。写真のクエスト・第2クエストの芽も、近くに出る小さな「はじめる」を押したときに始まります。
- 小さな案内（「話す／しらべる／はじめる」）は、2m 以内で、あいだに木の幹や岩がないときだけ出します。いちばん近くて、ヒロリの前にある1か所だけです。出ている案内は 2.6m まで保ちます。ほかの相手がはっきり近いときだけ切りかえるので、境目で点滅しません。
- カメラとヒロリ（パネルを開いているときは調べる物も）のあいだに木や立ち石がかかったら、点を抜いて透かします。かかったら約0.2秒で薄くし、はずれても0.5秒は薄いまま待ってから、約0.45秒かけて戻します。

## 発見の演出

どの演出も、3D の世界で見せてから説明のパネルを出します。
ごほうびは演出を始める前に決めて保存するので、連打しても、途中で閉じても、読み込みなおしても、二重にはもらえません。

| 場面 | 長さ | 流れ | 色 |
|---|---|---|---|
| 宝箱 | 2.4 秒 | 少しゆれる → ふたが開く → 光がもれる → ランタンとかけらが出て浮かぶ → ヒロリのところへ（手に入れた表示） | 金色の光の筋と粒 |
| ランタン | 0〜2.0 秒 | 灯りがともる → ほらあなの入口と壁が照らされる → 壁の絵が浮かぶ | だいだい色 |
| ひみつ | 2.0〜3.6 秒 | 絵の中の大きな木が光る → 光の粒が遠くの大きな木のほうへ → 遠くの木の光がふくらむ | 青白い色 |

- ランタンとひみつは、続けて起きる1つの演出（`EV_DUR.cave` = 3.6 秒）です。
- 「動きを減らす」設定の端末では、同じ順番を 0.6 秒で見せ、ゆれ・粒・ちらつきを止めます。
- 効果音はその場で作る短い音です。音のファイルは使いません。最初に画面へふれたあとから鳴ります。
- 強い点滅は使いません。長く待たせることもしません。
- 演出に使う物の描き方と絵は、読み込みのときに用意します（`warmUp`）。はじめての演出で、1コマが止まらないようにするためです。

## 重さの目安

採用した版をヘッドレス Edge（GPU：Intel Iris Xe・D3D11）で測った値です。
演出を変えたら同じ方法で測り、ここより大きく悪くならないことを確かめます。

| 区間 | スマホ幅（390×844、拡大率2倍） | PC（1280×800） |
|---|---|---|
| 西の草原（演出なし） | 60fps・JS p95 1.6ms | 60fps・JS p95 2.0ms |
| 宝箱 | 60fps・JS p95 1.4ms・最大 3.3ms | 60fps・JS p95 1.9ms・最大 5.7ms |
| ランタン | 60fps・JS p95 1.2ms | 60fps・JS p95 1.9ms |
| ひみつ | 60fps・JS p95 1.3ms | 60fps・JS p95 2.2ms |

JS は、描画ループの中の1コマの処理時間です。p95 は、95% のコマがこの時間以下だったという意味です。
