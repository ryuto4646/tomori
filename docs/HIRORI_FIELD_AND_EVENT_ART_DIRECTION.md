# ヒロリの見せ方：Field（探索）と Event（冒険の節目）

TOMORI のヒロリを、2つの表現に分けて作るための方針。
この文書は設計を決める（Step 11K-B・2026-10-06）。
Field 版は Step 11L-A（2026-10-06）で作り、ゲームに入れた。生成スクリプトは `tools/hirori-field/generate_hirori_field.py`、GLB は `assets/hirori-field/hirori-field.glb`（2,758 三角形）。
GLB を読めないときは、今までの仮ヒロリのまま進む。`demo-world.html?hirori=placeholder` で仮ヒロリに固定できる。
Event 版はまだ作っていない。

## 1. 基本の考え方

| 表現 | 使う場面 | 形 | 三角形の数 |
|---|---|---|---|
| Field Hirori | ふだんの探索（歩く・止まる・発見する） | ちんちくりんの低ポリ3D | 2,000〜5,000 目標・8,000 上限 |
| Event Hirori | 冒険の節目（5つの場面） | まず精巧な2Dイラスト。将来は高精細3Dも検討 | 3Dにする場合は 25,000 目標・40,000 上限 |

ふだんの画面では、形を大胆にまとめた低ポリで、愛着のわく姿を見せる。
大切な場面だけ、精巧な表現で気持ちの動きを見せる。
参考にするのは「ふだんは大胆な低ポリ、節目では精巧な表現」という設計の考え方だけである。
特定の作品のキャラクター・形・モデル・素材は、まねもコピーもしない。

## 2. Field Hirori（探索用）

### 体の比率

- 2.3〜2.7頭身
- 頭は全高の約38〜42%
- 大きな頭、小さな胴、短い脚
- 大きな3本指の足
- 羽は少し大きめに誇張する

### 守る特徴（正式な設定画像と同じ）

- 色は3色が中心：珊瑚色（体の外側）・クリーム色（顔・のど・胸・おなか）・淡い水色（羽の内側・とさかの内側）
- とさかは4枚。頭のまんなかの線の上に、顔側から後頭部へ一直線に並ぶ
- 先頭（顔側）のとさかが最も大きく、うしろへ順に小さくなる
- 鼻・尻尾・腕・手・耳・角はない

### とくに大きく見せる5つの特徴

遠くから見ても「ヒロリだ」と分かるように、次の5つを強めに見せる。

1. 上・うしろへ流れる4枚のとさか
2. 珊瑚色の体
3. 水色の内側が見える羽
4. クリーム色の顔と胸
5. 大きな3本指の足

### 低ポリの表現

- 面が少し見えるくらいの低ポリにする（なめらかにしすぎない）
- 画面の小さなスマホでも、遠景でも、とさかと羽の形で見分けられる
- 三角形は 2,000〜5,000 を目標、8,000 を上限とする

### 動きに向いた作り

あとで次の動きを付けやすい構造にする。

- 歩く・走る・止まる
- 転ぶ・悩む
- 発見する
- ことばのタネを抱える

部位は、`HIRORI_V3_EXTERNAL_MODEL_SPEC.md` の部位名（Root・Body・Head・Wing・Leg・Foot・Crest_01〜04・Eye）に分けておく。

## 3. Event Hirori（冒険の節目の5場面）

### 最初は2Dイラストにする理由

- 表情・羽の動き・光を、短い時間で細かく見せられる
- スマホでも描画の負担がほとんど増えない
- 高精細3Dは、制作・確認・性能の負担が大きい。Field 版が固まってから検討する

### 5つの場面

| 場面 | 見せたいこと | 長さの目安 |
|---|---|---|
| ことばのタネ誕生 | 自分のことばから、タネが生まれた驚き | 1.5〜2秒 |
| タネ取得 | タネを大事に抱える | 1〜1.5秒 |
| 根の門開放 | 門がタネに応えた手ごたえ | 1.5〜2秒 |
| ことばの樹点灯 | 世界が灯ったうれしさ | 2〜3秒 |
| 冒険完了 | ここまで来た達成感と、つづきへの期待 | 2〜3秒 |

### 画面での配置

| 項目 | PC（1280×800） | スマホ（縦長・幅320〜430） |
|---|---|---|
| ヒロリが占める広さ | 画面の高さの約35〜45% | 画面の幅の約55〜70% |
| ヒロリの位置 | 中央からやや左 | 中央（上下の文章と重ねない） |
| タネ・樹 | ヒロリの右側、または手もと | ヒロリの手もと（タネ）／背景の上部（樹） |
| 文章 | 下部の帯に1〜2行 | 下部の帯に1〜2行。上部の案内と同じ文を重ねない |

- 3Dの世界を完全に隠さない。背景を少し暗くして、その上に重ねる
- 文章は既存の上部の案内・完了の枠と同じ言葉を使い、新しい説明文を増やさない

### 時間と操作

- 1つの演出は1〜3秒
- 操作を長く取り上げない。画面のタップ（またはキー操作）ですぐに閉じられる
- 演出が終わったら、もとの探索へそのまま戻る（ヒロリの位置・カメラは変えない）
- 同じ場面の演出は、冒険1回につき1度だけ出す（リセット後はもう一度出る）

### reduced-motion（動きを減らす設定）

- 拡大・回転・移動のアニメーションをしない。イラストは止まった1枚で見せる
- 表示の時間は通常と同じか、短くする
- 光の点滅はしない

## 4. Field 版と Event 版をそろえるきまり

- 色：珊瑚色・クリーム色・淡い水色の3色を同じ値で使う（Event 版のイラストも、Field 版の頂点色・素材の色に合わせる）
- とさか：どちらも4枚・中央線上・顔側が最大。Event 版でも左右に対で置いたり、花のように広げたりしない
- 羽：どちらも1枚の柔らかな翼で、内側が水色。羽根を何枚も並べない
- 足：どちらも丸い3本指。爪・水かきはない
- 2つを並べたとき、とさかの枚数・並び・色の順番が一致しているかを、人の目で確かめる

## 5. 今の仮ヒロリからの差し替え

いまのゲームは `demo-world.html` の `character = createHiroriPlaceholder();` で仮ヒロリを作っている。
差し替えは、次の順番で行う（どれも別の Step で、HQ の判断のあとに行う）。

1. Field 版の GLB を `node tools/validate-hirori-v3.mjs --profile field <ファイル.glb>` で検査し、合格したものだけをリポジトリへ入れる
2. `GLTFLoader` で読み込み、読み込めたときだけ `character` を差し替える
3. GLB は全高 約1.0 で作る。仮ヒロリは全高 約2.0 なので、読み込む側で2倍に拡大して同じ大きさにそろえる
4. 足もと（Y=0）・正面（+Z）・頭の上のラベルの位置を、仮ヒロリと同じにする
5. 動きのクリップ名を `ANIM_MAP`（idle・walk・discover・celebrate）に合わせる
6. Event 版のイラストは、場面ごとに1枚ずつ用意し、上の5場面の切りかわりで表示する

### 読み込みに失敗したとき

- Field 版の GLB が読めない・時間切れのとき：仮ヒロリのまま進める（今と同じ見た目・同じ操作）
- Event 版のイラストが読めないとき：演出を出さずに、今の上部の案内と完了の枠だけで進める
- どちらの場合も、冒険の進み方・タネの取得・門・樹の判定は変えない。console へのエラー表示もしない

## 6. 検査ツールの使い分け

```
node tools/validate-hirori-v3.mjs --profile field <ファイル.glb>
node tools/validate-hirori-v3.mjs --profile event <ファイル.glb>
```

- `--profile` を付けないときは `event` として検査する
- field：三角形 2,000〜5,000 が目標（外れると注意）、8,000 をこえると不合格
- event：三角形 25,000 以下が目標（こえると注意）、40,000 をこえると不合格
- 形式・大きさ・名前・個人のパスの検査は、どちらも同じ

Step 11J のヒロリ（19,650 三角形）を検査した結果は次のとおり。

- event：合格
- field：不合格（上限 8,000 をこえるため）

Field 版は、低ポリに合う形を最初から設計し直す想定である。11J のモデルは Event 版の3Dを検討するときの参考にする。

## 7. 人が確かめること

- 新しいモデル・イラストが、特定の作品のキャラクターに似すぎていないか
- 外部のサービスや制作者に頼む場合の利用規約・権利（`HIRORI_V3_EXTERNAL_MODEL_SPEC.md` の5章）
- Field 版と Event 版を並べたときに、同じヒロリに見えるか
