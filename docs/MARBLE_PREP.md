# Marble 導入の準備（巨木のある聖域）

確認日：2026-10-20。契約・課金・有料生成はしていません。導入を判断するための準備だけです。

対象は「巨木のある聖域」1エリアです。アプリ全体の描画方式は置きかえません。Marble の素材を待つあいだも、今の基本の形のモデルで開発を続けます。

## 1. 公式の情報（確認日 2026-10-20）

### 料金・プラン

- 公式の料金ページ（marble.worldlabs.ai/pricing）は、画面を組み立てる仕組みのため、文字を読み取れなかった。**契約の前に、料金ページを人の目で確かめる必要がある。**

### 利用条件（利用規約 2026-01-21 版）

- **18歳以上（またはその国の成年）でないと使えない。** 使うアカウントは大人（保護者・制作者側の大人）が持つ必要がある。
- 無料のアカウントで作ったものは World Labs の権利になる。使えるのは、個人で、商用でない範囲だけ。
- 有料のアカウントで作ったものは、作った人のものになる。商用も含めて使える（規約 3.3(b)）。ただし公式ドキュメントには「商用の権利は Pro から」とも書いてあり、**表現が合っていない。契約前に確認が要る。**
- アップロードした画像などは、World Labs の学習に使われる。無料のアカウントでは取り消せない。有料のアカウントでは、設定から止められる。
- 透かしや帰属表示を消してはいけない。

### 書き出しの形式

| 種類 | 形式 | 大きさ | プラン | 用途 |
|---|---|---|---|---|
| スプラット | SPZ・PLY | 約200万個（全体）／約50万個（軽い版） | Standard | 見た目（いちばんきれい） |
| 当たり判定メッシュ | GLB | 10万〜20万三角形、3〜4MB | Standard | 歩く・ぶつかる（見た目には使わない） |
| 高品質メッシュ | GLB | 質感つき 約60万三角形（100〜200MB）／頂点色 約100万三角形 | Pro | 見た目（作るのに最大1時間。取り消せない） |
| パノラマ | PNG（2560×1280） | 1枚 | Standard | 背景の空・遠景 |

- 座標は OpenCV の向き（+x 左・+y 下・+z 前）。three.js で使うときは、Y と Z を反転する。大きさ（1単位が何mか）は書かれていない。

### three.js での表示（Spark）

- Spark：World Labs が公開している、three.js 用のスプラット表示（MIT ライセンス）。`@sparkjsdev/spark`（例では 2.3.1）。
- `SplatMesh` は three.js の物と同じように置けて、ふつうのメッシュといっしょに描ける（公式の説明）。
- WebGL2 が必要。スマホでも速いと書かれているが、具体的な目安はない。
- Spark 2.0 からは、遠くを粗く・近くを細かく読む仕組みがある。`.rad` 形式を、少しずつ読みこむ。説明ページは作成中。
- **公式の例は three.js 0.180 を使っている。TOMORI は 0.160。** 0.160 で動くかは書かれていない。
- 公式の作例では、スプラットの見た目と当たり判定メッシュを組み合わせ、Rapier という物理のしくみでキャラクターを歩かせている。

## 2. TOMORI への取り込み方

### おすすめの組み合わせ

| 役わり | 使う物 | 理由 |
|---|---|---|
| 景色（地面・巨木・草木・空気感） | スプラットの軽い版（約50万個） | いちばんきれいで、スマホにいちばん軽い |
| 歩ける地面の高さ | 当たり判定メッシュ（下向きの光線で高さを読む） | 今の `heightAt` を、聖域の中だけ置きかえる |
| 歩ける範囲・ぶつかる所 | **今の TOMORI のしくみのまま**（道・広場・幹・オオネの体） | 進み方と歩ける範囲をゲームの側で決めたままにできる。Rapier を足さなくてすむ |
| オオネ・門・植える場所・橋・光の演出 | **今の three.js の物のまま**、同じ座標に置く | 動き・開く・育つ・保存を、今のコードで続けられる |

- 生成する景色には、大きな生きもの・橋・門・文字を入れない。動く物や変わる物は、ゲームの側で置く。
- 景色の Spark は、門がひらいたあと（または巨木への道に入ったとき）にだけ読み込む。最初の読み込みは今のまま。

### 追加が要るもの・既存の機能への影響

| 追加 | 影響 |
|---|---|
| Spark（`@sparkjsdev/spark`） | 新しい外部のライブラリ。今の「アプリに新しい CDN・パッケージを足さない」決まりの例外になるので、判断が要る |
| three.js 0.160 → 0.180（必要なら） | アプリ全体に影響する。色の扱い・影・素材・自前の GLB 読み込み・テスト（CDN の一覧）を、すべて確かめ直す必要がある |
| GLTFLoader（当たり判定の GLB） | three.js と同じ場所から読む部品。今のアプリは使っていない |
| WebGL2 | ほぼすべての端末で使えるが、使えない端末では今の景色のままにする |

### 総作業量の見積もり（目安）

| 工程 | 目安 |
|---|---|
| 生成と作り直し（プロンプトの調整・3〜6回） | 1〜2日 |
| 検証ページで確かめる（容量・読み込み・フレーム時間・位置合わせ・歩行） | 1日 |
| three.js を上げる場合の確かめ直し（全テスト・4画面・実機） | 2〜4日 |
| 聖域へ組み込む（読み込みの分割・地面の高さ・今の物との重なり） | 2〜3日 |
| 実機の確認と調整（iPhone） | 1日 |
| **合計** | **約1.5〜2.5週間**（three.js を上げない方法で動けば、約1週間） |

## 3. 確かめていないこと（検証項目）

次の項目は、まだ確かめていない検証項目です。素材を受け取ったら、検証ページで1つずつ確かめます。

1. Spark が three.js 0.160 で動くか。動かなければ、0.180 へ上げたときの影響。
2. スプラットと、今のメッシュ（オオネ・門・橋）の前後関係が正しく描かれるか（オオネが景色の中に沈んで見えないか）。
3. 生成された世界の大きさ（1単位が何mか）と向き。配置案（巨木の中心 x=-22.8, z=-28.9）に合わせられるか。
4. 当たり判定メッシュの地面が、スプラットの見た目の地面とずれていないか（足が浮く・沈む）。
5. スマホ（iPhone）での読み込み時間とフレーム時間。軽い版（約50万個）で 60fps に近いか。
6. スプラットの霧・色が、ヒロリや今の草原と合うか（境い目が目立たないか）。
7. 生成した景色に、意図しない生きもの・文字・人工物が入っていないか。
8. 透かし・帰属表示の要否と、置き方。
9. 料金ページの最新の金額と、Standard での商用利用の可否。

## 6. 素材を受け取ったあとの検証ページ

`tools/marble-check/index.html`（アプリからは読み込まない、独立したページ）

1. 開発用のサーバーで `tools/marble-check/` を開く（例：`http://localhost:3458/tools/marble-check/`）。
2. 「スプラット」に .spz（まず軽い版）、「当たり判定」に collider の .glb を選ぶ。ファイルは、この端末の中で読むだけで、どこへも送らない。
3. 「OpenCV → three」をオンのまま、大きさ・回転・X/Y/Z を動かし、配置の目印（入口・巨木・オオネ・植える場所・橋・向こう岸）と景色を合わせる。合った値を記録する。
4. 「入口」「広場（会話）」「橋」のボタンで、ゲームに近い構図から見る。同じ構図の今のゲームの画面と並べてくらべる。
5. 「歩く」をオンにして、WASD・矢印キーで歩き、地面に沿うか、壁で止まるかを見る。
6. 「フレーム時間を5秒測る」を、PC とスマホで押す。

### 実測する項目

| 項目 | 測り方 | 目安 |
|---|---|---|
| ファイル容量 | 検証ページに出る（スプラット・当たり判定） | スプラット 30MB 以下（スマホ） |
| 初回読み込み時間 | 検証ページに出る（選んでから表示まで）。ゲームでは門がひらいてから見えるまで | 3秒以内（スマホ） |
| フレーム時間 | 「フレーム時間を5秒測る」（p50・p95・最大） | p95 が 20ms 以下 |
| 見通し | 「広場（会話）」の構図で、オオネとヒロリが景色に埋もれないか | 顔とヒロリが見える |
| 歩行と衝突 | 「歩く」で、道・広場・川の手前を歩く | 足が浮かない・沈まない、川へ入らない |
