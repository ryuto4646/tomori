## 3D画面を追加する場所

### 方針A：独立ページ方式（推奨・2週間向け）

`demo-world.html` を独立ファイルとして用意し、`index.html` からボタンで開く。
既存コードへの影響ゼロ。2週間で実装しやすい。

```
index.html
  └─ 「3Dで探索する」ボタン → demo-world.html（新規）
       └─ ミッション到達 → URL パラメータで index.html に戻り既存フローへ接続
```

### 方針B：インライン統合方式（3週間以降向け）

`screen-worldmap` 内に Three.js キャンバスを埋め込み、完全統合する。
既存の静的背景との共存・モバイルパフォーマンス確認が必要なため、方針Aの成功後に移行する。

**実装は方針Aで進める。**

## 技術的な危険箇所

### 1. スマートフォン性能

**リスク**: Three.js のシャドウマップや高ポリゴンで fps が落ちる。

**対策**:
- `renderer.shadowMap.enabled = false` を基本に
- 地面・木は ProceduralGeometry（100–500 triangle）
- GLB モデルは 3000 triangle 以下を推奨（詳細は ASSET_REQUIREMENTS.md）
- `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))`
- 描画解像度を下げるフォールバック（1.5x → 1x → 0.75x）

### 2. ネットワーク障害（TV収録リスク最大）

**リスク**: /generate や /feedback が返らず、収録が止まる。

**対策**:
- 収録日の 2 日前にデモシナリオ全パターンの AI レスポンスを取得してローカルに保存
- `DEMO_OFFLINE_CACHE` 配列にハードコード（tomori-api の既存フォールバックと同じ手法）
- `/generate` が 3 秒以内に返らなければキャッシュから返す
- Worker のフォールバックレスポンスはすでに実装済み（parseMissions のハードコード）

### 3. GLB モデル未受領

**リスク**: 収録日までに正式モデルが届かない。

**対策**:
- カプセル仮モデルは見た目の目的を果たせる形に整える（色・比率）
- GLB が届いた際に 1 ファイルを置くだけで差し替わる構造を最初から実装
- モデルのアニメーション名が不明な場合のフォールバック（全クリップ取得して最初のを使う）

### 4. iOS Safari の制約

**リスク**: `SpeechRecognition` は iOS では `webkitSpeechRecognition` のみ有効。
TouchEvent が WebGL canvas と干渉する場合がある。

**対策**:
- 既存の `startVoiceInput()` がすでに `webkitSpeechRecognition` に対応済み
- canvas の `touch-action: none` を設定
- カメラ入力は `<input capture>` を使う既存方式を流用（WebRTC不使用）

### 5. Three.js 未対応ブラウザ

**リスク**: 古い端末で WebGL が無効。

**対策**:
- `WebGL.isWebGLAvailable()` チェック（three.js 同梱）
- 失敗時は「通常モードで続ける」ボタンを表示 → `index.html` へリダイレクト

### 6. `index.html` 肥大化（将来リスク）

**リスク**: 現在の 7056 行に 3D コードを直接追記すると可読性が崩壊する。

**対策（Day 3 以降）**: インライン統合する前に、3D コードを `/src/world3d.js` に分離してから `<script src>` で読み込む形にする。検証段階では `demo-world.html` を独立させることでリスクを回避する。

## 本番用とデモ専用機能の区別

| 機能 | 本番 (`DEMO_MODE=false`) | デモ (`DEMO_MODE=true`) |
|---|---|---|
| ミッション数制限 | なし | 3回で終了（既実装） |

| シークレットミッション | 条件判定 | 固定トリガー可能 |

## テレビ収録時のオフライン・失敗対策

### オフライン対応レベル別プラン

| レベル | 条件 | 対策 |
|---|---|---|
| Level 0（理想） | 安定 Wi-Fi あり | 通常動作 |
| Level 1（推奨） | Wi-Fi 不安定 | 3秒タイムアウト→キャッシュ |
| Level 2（最悪） | 完全オフライン | 全 AI レスポンスをハードコード |

### 収録日前チェックリスト

```
□ デモシナリオ3パターンのAIレスポンスをキャッシュ済み
□ DEMO_TV_MODE = true に設定済み
□ 収録端末でローカルHTTP起動確認（python -m http.server）
□ 60fps 動作確認
□ 写真撮影→ミッション→フィードバック フル通し完了
□ GLB差し替え後の動作確認（モデル受領済みの場合）
□ 「3Dが失敗した場合」のフォールバック動作確認
□ 機内モードで全フロー動作確認
```

### 緊急時の切り替え手順

3D世界が起動しない場合、次の URL で既存アプリに即座に戻れる：

```
index.html  （3D不使用の通常フロー）
```

`demo-world.html` は `index.html` から独立しているため、3D が失敗しても既存アプリは無傷。
